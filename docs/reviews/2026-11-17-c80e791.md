# Review of c80e791 (2026-11-17)

An outside review of `6af2003..c80e791` (26 commits). Status of each finding is tracked in
`docs/TODO.md`; this file keeps the detail.

## High

1. **Human whispers also go to playerbots' command handler.** `Playerbots.CommandPrefix` was
   empty, so "who", "invite", "leave"... in a whisper ran as playerbots commands beside the
   brain's reply (a GM's whispers are all parsed as commands). Bot senders are silent, so tests
   never showed it. **Fixed:** `Playerbots.CommandPrefix = "!pb "` in `config/playerbots.overrides`.
2. **A watch that is still true fires after every plan.** `SetPlanContext` cleared the latches, on
   plan install and on the first streamed line: `hp<40` at a flat 33% woke the bot every snapshot,
   each wake stopping the plan. **Fixed:** latches start from the last snapshot; the first line
   only sets expected names (`SetExpectedNames`).
3. **A Loot step can't finish if the body leaves items.** Done means "corpse not `lootable`"
   (`plan_runner.cc`), true while one item is left; playerbots skips items it has no use for, and
   vendor junk when bags are over 80% full. The step times out and `Loot X` stays on screen (the
   TODO "loot timed out twice"). **Fixed:** the done signal (below); a Loot step is pending while
   the corpse is playerbots' loot target or the open loot window (`IsLootInProgress`). Loot is
   still offered on a corpse with items left (a player sees it sparkle too).
4. **Gather/Use on a chest refused beyond 15 yd and with bags over 80%.** Playerbots' `use` refuses
   past `LootDistance` = 15 yd, and `IsLootPossible` refuses with bags > 80% or height > 3 yd
   (`UseItemAction.cpp`). Explains TODO "Gather refused" (a missing strategy is ruled out).
   **Fixed:** out of range, the bot walks first and uses it on arrival (`IsInUseRange`,
   `UseOnArrival`); a refusal returns playerbots' reason (`WhyCantUse`: distance, height, bags,
   quest, casting, looting, skill/tool/key). The snapshot now fills `bag_free_slots`.
5. **Eval, goldens and RULES.md use options live bots never see.** No fixture has `options` (0/48,
   0/10), so the harness invents Explore/Rest/Town/Talk; live has only
   Attack/Loot/Gather/Use/Keep. 10-13 eval cases need a non-existent option, and the default model
   was picked on this score. **Fixed for the eval:** `fixture_options` (the module's `AddOptions`)
   + `tools/snapshot/add_fixture_options.py` write the live options into 37 eval snapshots
   (checked by `wlb check`); the 13 that need Talk/Rest/Explore/Town are `planned` (scored only
   with `wlb test eval planned`); RULES.md no longer mentions them. The 10 screen goldens are
   left without options: they test rendering against the Python prototype.
6. **A failed build in `wlb test` leaves the play server down or the test build installed.**
   `Stack.restore()` stops at the first failure (`testing.py`), and `built_flavor()` reads the
   CMake cache, not what's installed. **Fixed:** each restore step is tried and failures reported
   together; the build is compiled before the server stops; `out/server/installed-flavor` is
   written after an install succeeds.

## Wire format

Probed with the pinned Glaze: zero/false optionals survive BEVE and JSON; 28,000 corrupted frames
gave no crash; depth capped at 256. **Done:** tests pin zero/false optionals and corrupt frames
(`snapshot_unittest.cc`); reads refuse strings over 64 KiB and arrays over 16384;
`WriteJson` returns "" instead of invalid JSON; every module message and command carries
`version` (`kWireVersion`), and each side drops and logs frames of another version.

## The done signal (Use and Loot)

Add `uint32_t done_command_id` to `Snapshot`. The module sets it when `active_option` stops pending
(Loot: off playerbots' loot list and `GetLootGUID()` empty) and clears it on connect;
`PlanRunner` treats a step as done when it matches `last_command_id_`. A field, not an event: a
newer snapshot can't lose it.
